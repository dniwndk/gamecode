# 탑뷰 전투 손맛 프로토타입 (Unity)

하데스식 탑뷰 액션의 **전투 손맛만** 빠르게 시험해 보는 유니티 프로토타입입니다.
그래픽·사운드는 모두 코드로 만든 임시 도트라서 에셋 없이 바로 돌아갑니다.

## 실행 방법 (1분)

1. `Assets/CombatPrototype` 폴더를 유니티 프로젝트의 `Assets/` 아래에 복사합니다.
2. 새 씬을 만듭니다 (File > New Scene, 빈 씬이면 됩니다).
3. 빈 GameObject를 하나 만들고 `CombatBootstrap` 컴포넌트를 붙입니다. `CombatTuning`이 자동으로 같이 붙습니다.
4. Play를 누릅니다.

- Unity 6 / 2022.3 기준으로 작성했습니다. 새 Input System과 예전 Input Manager 둘 다 동작합니다.
- URP 2D 프로젝트에서 2D 라이트가 없으면 전역 2D 라이트를 자동으로 추가합니다(스프라이트가 검게 보이는 문제 방지).
- 패키지 의존성은 없습니다.

## 조작

| 입력 | 동작 |
| --- | --- |
| WASD / 방향키 | 이동 |
| 마우스 왼쪽 / J | 공격 (3타 콤보, 마지막 타는 강타) |
| Space / Shift / 마우스 오른쪽 / K | 대시 (무적 프레임 + 잔상) |
| 대시 중 공격 | 대시 공격 |
| M | 조준 방식 전환 (마우스 ↔ 이동 방향) |
| 게임패드 | 왼스틱 이동, 오른스틱 조준, X(서쪽) 공격, A(남쪽) 대시 |

## 손맛 비교 토글

플레이 중 숫자 키로 요소를 하나씩 끄고 켜면서 차이를 느껴 보세요. (The Art of Screenshake 방식)

| 키 | 요소 | 끄면 생기는 일 |
| --- | --- | --- |
| 1 | 히트스톱 | 맞는 순간의 멈춤이 사라져 타격이 가볍게 느껴짐 |
| 2 | 화면 흔들림 | 충격의 크기가 전달되지 않음 |
| 3 | 넉백 | 맞은 결과가 위치로 안 보임 |
| 4 | 히트 플래시 | 맞았는지 눈으로 확인하기 어려움 |
| 5 | 입력 버퍼 | 공격 도중 미리 누른 입력이 사라져 콤보가 끊김 |
| 6 | 대시 캔슬 | 공격 후딜 중 대시로 빠져나갈 수 없음 |
| 7 | 에임 보정 | 조준이 조금만 빗나가도 헛스윙 |
| 8 | 스파크 | 타격 지점 이펙트 없음 |
| 9 | 사운드 | 효과음 없음 |
| 0 | 전체 켜기/끄기 | |
| T | 슬로모션 x0.25 (프레임 단위로 관찰) | |
| R | 리셋 | |
| Tab | HUD 숨기기 | |

화면에는 허수아비 1개(공격하지 않고 죽지 않음)와 추적형 적 3마리가 나옵니다.
적은 빨갛게 깜빡이며 예고한 뒤 돌진하므로, 대시 무적 프레임으로 피하는 연습을 할 수 있습니다.

## 수치 조정

플레이 중 `CombatTuning` 인스펙터에서 바로 바꿀 수 있습니다. 프레임 값은 모두 60fps 기준입니다.

- **콤보(combo)**: 타마다 `startup`(선딜) / `active`(판정) / `recovery`(후딜), 데미지, 사거리, 넉백, 히트스톱 프레임, 흔들림 픽셀
- **Feel strength**: 히트스톱·흔들림·넉백 배율(0~3)
- **Player**: 이동 속도, 대시 속도·길이·무적 프레임·쿨다운, 입력 버퍼 길이(기본 0.15초), 콤보 리셋 시간
- **Enemies**: 수, 체력, 속도, 예고 프레임, 경직 프레임

인스펙터에서 바꾼 값은 Play를 끄면 되돌아갑니다. 마음에 드는 값은 컴포넌트 메뉴의 Copy Component → 정지 후 Paste Component Values로 옮기면 됩니다.

## 기존 스파크 FX 연결 (선택)

프로젝트 파일의 `spark-fx/library/hit-spark.png`를 타격 이펙트로 쓸 수 있습니다.

1. `hit-spark.png`를 Assets에 넣고 Texture Type = Sprite (2D and UI), Sprite Mode = Multiple, Filter Mode = Point, Compression = None으로 설정합니다.
2. Sprite Editor > Slice > Grid By Cell Size = 136 x 80 으로 자릅니다 (4 x 4 = 16프레임).
3. 크기가 크면 Pixels Per Unit을 올려 맞춥니다 (캐릭터는 16 PPU 기준).
4. 잘린 16개 스프라이트를 `CombatBootstrap`의 `Hit Spark Frames` 배열에 순서대로 드래그합니다. 재생 속도는 `Hit Spark Fps`(기본 30)입니다.

## 파일 구성

| 파일 | 내용 |
| --- | --- |
| `CombatBootstrap.cs` | 카메라·아레나·플레이어·적을 코드로 생성 |
| `CombatTuning.cs` | 모든 수치와 토글 |
| `PlayerController.cs` | 이동, 3타 콤보(선딜/판정/후딜), 대시·무적·대시 캔슬, 입력 버퍼, 에임 보정 |
| `Enemy.cs` | 추적 → 예고 → 돌진 → 휴식, 피격 경직, 허수아비 |
| `Combatant.cs` | 공통: 개별 히트스톱(멈춘 대상만 시간 정지), 넉백(히트스톱 뒤 적용), 히트 플래시, y 정렬 |
| `Feel.cs` | 히트스톱·흔들림·스파크·사운드·카메라·토글·HUD |
| `PixelArt.cs`, `SfxGen.cs`, `FxBits.cs` | 임시 도트 스프라이트, 합성 효과음, 파티클/잔상 |

설계 메모: 히트스톱은 `Time.timeScale`을 건드리지 않고 공격자와 피격자만 멈춥니다. 그래서 여러 적을 동시에 때려도 다른 적은 계속 움직이고, 입력은 멈춘 동안에도 버퍼에 쌓입니다.
