# 《황동의 생애》 제작 기획서 1장 (game-blueprint)

> 원본: `황동의_생애_게임_상세기획서.docx` (38장). 이 문서는 그 원본을 **코드로 옮기기 위한 1장짜리 설계 확정본**이다.
> 원본의 수치·확률·규칙을 그대로 따르고, 이번 빌드에서 **무엇을 만들고 무엇을 미루는지**, **무엇이 되면 완성인지**를 못 박는다.

## 0. 한 줄 요약과 이번 빌드 범위

마법공학 도시 에르덴(공력 184년)에서 무작위로 태어난 13세 시민이 **한 해에 주 활동 1개 + 보조 약속 1개**를 고르고, 네 계절이 자동 처리되다가 **중요한 사건에서 멈춰 2~4개 선택**을 하며, 은퇴·생애 종료·이주로 **장례식과 연대기 결산**까지 가는 웹 게임.

| 단계 | 내용 | 이번 빌드 |
|---|---|---|
| **1차 빌드 (수직 시제품 확장판)** | 전체 규칙 엔진·저장·도시 시뮬레이션·UI를 완성하고, 13세부터 결산까지 끊기지 않는 한 삶. 구역 3, 직업 3, 핵심 인물 4, 공명 4, 사건 노드 34, 엔딩 6 | ✅ **이번에 만든다** |
| 2차 (최소 출시 버전 완성) | 독립 사건 48 + 연속 사건 3×4 = 60노드, 개인 목표 12, 업적 확대 | 이후 |
| 3차 (정식 확장) | 히든 루트 H01~H32, 업적 168, 운 전용 U01~U06, 10구역·12직업·8세력 | 이후 |

원본 23장의 "사건 수를 늘리기 전에 사용자가 이전 선택의 영향을 이해하는지 확인한다"를 따라, **엔진과 UI는 최종 규모로, 콘텐츠는 1차 범위로** 만든다. 콘텐츠는 JSON 데이터라 2·3차에 코드 수정 없이 추가된다.

## ③ 도시 자율 변화와 사건 디렉터 (= 적 AI에 해당)

플레이어가 아무것도 안 해도 도시는 움직여야 한다. **구체 수치로 고정**한다.

### 3-1. 도시 상태
- 전역 7지표: 공급 안정·물가(지수)·고용·공해·시민 신뢰·세력 긴장·잔흔 축적 (물가 외 0~100)
- 구역 4지표: 열 공급·일자리·공해·치안 (0~100) → 화면엔 안정/주의/위기 + 원인 한 줄
- 공급/수요: 시작 공급 110, 수요 100. 계절 보정(겨울 수요 +12, 여름 −8), 점검 부족 시 공급 −2/계절, 사고 −5~−15
- 부족률 = `max(0, 수요−공급) / max(1, 수요)`. 부족률 0.05 초과 시 다음 계절 공급 안정 −3, 물가 +2, 정전 사건 가중치 ×(1+부족률×10)
- **지표 계절당 변동 상한 ±6** (한 사건으로 도시가 튀지 않게). 개인 행동 ±1~3, 지역 프로젝트 ±5~10

### 3-2. 세력 4곳의 연간 계획 (매년 연초 1개씩)
| 세력 | 조건 | 행동 | 효과 |
|---|---|---|---|
| 시정청 | 공급 안정 < 50 | 점검 강화 / 통제 강화 | 공급 +4 또는 치안 +3·시민 신뢰 −3 |
| 황동 동업회 | 고용 > 60 이면 투자, 아니면 가격 인상 | 설비 투자 / 가격 인상 | 일자리 +4·공해 +2 / 물가 +3 |
| 적동 노동연맹 | 최근 2년 사고 ≥ 2 또는 긴장 > 60 | 파업 준비(긴장 +8) → 다음 해 파업 or 협상 | 파업 시 공업대 일자리 −10, 1년 |
| 등불 상호회 | 재의 골목 열 공급 < 40 또는 물가 > 110 | 공동 배급 / 난로 정비 | 재의 골목 열 +5 또는 식비 −2 |
자금·인력을 실제 차감하고, 같은 자원으로 두 계획을 동시에 완수하지 않는다.

### 3-3. 위기 시계 (0~6)
1차는 **공급망 단절** 시계 하나만 활성 (제2심장·잔흔은 3차). 부족률 > 0.08인 해 +1 (동일 원인 연 1회), 플레이어/세력 대응 성공 시 −1. 4 공개 경고 → 5 대응 기회 사건 → 6 국면 전환(구역 정전 1년, 물가 +10).

### 3-4. 사건 디렉터 (원본 15장 그대로)
- 해마다 **주요 선택 사건 1~2개 + 일상 기록 2~4줄**
- 선정 순서: 만기된 약속·긴급 안전 → 진행 중 연속 사건 → 직업·관계 후보 → 우연
- 자격 필터: 나이·구역·직업·인물 생존·자격·계절·선행 플래그
- 가중치 `weight = base × relevance(0.5~2) × city_factor(0.5~2) × novelty(새 1.0 / 최근 유형 0.25)`
- 쿨다운: **같은 사건 ID 5년, 같은 유형 1년**
- 연속 2회 심각한 손실 → 2년 안에 회복 기회 1개 제시 (판정 보정 아님)
- 지연 결과: `after_years [2,4]` + 재검사 조건 + 무효 시 대체 마무리(편지·유품·후임)

### 3-5. 난수와 재현성
- 시드 128비트 → 복사 가능한 문자열. 흐름 분리: 출생 / 도시 / 사건 / 판정 / 행운(1차 미사용)
- 화면 연출은 난수를 쓰지 않는다. 저장에 각 흐름의 상태 포함 → 새로고침해도 재추첨 없음

| `1`~`4` | 현재 표시된 선택지 선택 (선택지가 있을 때만 활성) |
| `Space` / `Enter` | 연대기 다음 줄 / 자동 진행 일시정지·재개 |
| `F` | 배속 순환 1×→2×→4×→8× (한 해 기본 20초) |
| `Esc` | 열린 패널 닫기 → 없으면 메뉴 |
| `Tab` / `Shift+Tab` | 초점 이동. 모든 버튼 포커스 링 표시 |

- 자동 진행 정지 조건: 중요한 사건, 비가역 선택, 사용자가 위임하지 않은 지출, 이전 기록을 펼쳤을 때, 탭이 백그라운드로 갔을 때. **타이머가 선택을 대신하지 않는다.**
- 선택지 키 `1~4`와 배속 키 `F`는 겹치지 않음. 텍스트 입력(이름 입력) 중에는 단축키 비활성.
- 터치 영역 최소 44×44 CSS px. 모바일 세로 360px 폭부터 지원.

## 기술 기본값

- **빌드 도구 없는 정적 웹**: `index.html` + ES 모듈. 외부 CDN 의존 0 (폰트도 로컬). 로컬 서버(`python3 -m http.server`)나 GitHub Pages로 바로 열림
- 폴더
  ```
  index.html
  css/        tokens.css · frame.css · screens.css · motion.css
  js/core/    rng.js · state.js · rules.js · economy.js · city.js · director.js · ending.js · save.js   ← DOM 비의존, Node에서 실행
  js/data/    backgrounds.json · npcs.json · jobs.json · events/*.json · endings.json · achievements.json · daily.json
  js/ui/      app.js · screens/*.js · components/*.js · motion.js · audio.js
  assets/svg/ 코너·리벳·톱니·게이지·다이얼·아이콘 스프라이트
  fonts/      RIDIBatang.woff2
  tests/      sim.test.mjs (headless) · e2e.spec.mjs (Playwright)
  ```
- 내부 시간은 **연도·계절 단위 고정**. 실시간은 연출에만 쓰고 배속이 결과를 바꾸지 않음
- 사건은 "상태를 직접 수정하는 코드"가 아니라 **허용된 효과 목록**(현금 증감·관계 변화·플래그·프로젝트 진척·후속 예약)으로만 표현 → 작가가 JSON만 고쳐 콘텐츠 추가
- 효과음은 WebAudio로 합성(증기·종·인쇄·공구) — 음원 파일 없이, 기본 꺼짐 아님/설정에서 끔

## 결정이 필요한 것 (승인 시 함께 확인)

1. **첫 빌드 범위**: 위 "1차 빌드(사건 34노드)"로 시작해 한 삶이 끝까지 도는지 먼저 검증 → 2차에서 60노드로 확장. (권장)
2. 나머지 원본 24장의 미정 항목은 다음 기본값으로 진행: 지원 기기 = 최신 데스크톱·모바일 브라우저, 묘사 강도 = 보통(설정에서 낮춤 가능), 1회 플레이 = 1차 콘텐츠 기준 약 20~30분, 그림 = SVG 장식과 실루엣 초상(일러스트 없음), 저장 = 브라우저 로컬 + 파일 내보내기(온라인 저장 없음).
