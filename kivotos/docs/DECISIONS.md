# 결정 기록

기획서(v2.1 + v2.2 개정안)에 없거나 해석이 갈리는 부분을 어떻게 정했는지 남긴다. 형식: 결정 · 이유 · 영향 ID.
바꿀 때는 줄을 지우지 말고 새 항목에서 "D-00N 대체"라고 적는다.

## M0 (2026-10-29)

**D-001 v2.2 개정안을 구현 기준에 포함한다.**
v2.2는 v2.1과 함께 넘기도록 쓰인 개정안이다(개정안 머리말). 콘텐츠 팩은 `ba-content-2.2.0`, 규칙은 `ktfr-rules-2.2.0`으로 만든다.
되돌리려면 추출기에서 v2.2 단계를 빼면 된다. 영향: 유닛 태그 9건·이름 1건, `syn_jackpot`, `str_kaiser_loan`, 효과 304개, rules.json 경제 수치.

**D-002 이 게임은 저장소의 `kivotos/` 하위 폴더에 둔다.**
저장소에는 이미 다른 게임 두 개(루트 「황동의 생애」, `name-remains/`)가 있다. 기획서는 빈 저장소 루트를 전제로 썼지만 같은 구조를 `kivotos/` 안에 그대로 둔다.
배포 경로는 `/gamecode/kivotos/`. 루트 게임의 서비스 워커가 같은 사이트의 모든 화면 요청을 가로채므로 `tools/build.mjs`의 제외 목록에 `/kivotos/`를 넣었다. 이 게임이 만들 저장소·캐시 이름은 `kivotos-`로 시작한다.

**D-003 화면 계층은 교체 가능하게 분리하고, UI 프레임워크는 화면 쪽이 정한다.**
UI는 따로 설계 중이다(사용자 지시, 2026-10-29). 기획서 12.1은 React를 지정하지만, 규칙 코드는 어떤 프레임워크에도 묶지 않는다.
화면은 `src/app/gameClient.ts`의 `GameClient`만 쓴다. M0의 임시 화면은 의존성 없는 바닐라 TS다. 정식 화면이 React를 쓰면 그때 `src/ui/`와 함께 넣는다.
규칙은 docs/UI_CONTRACT.md, 강제는 tests/unit/architecture.test.ts와 tsconfig.core.json.

**D-004 콘텐츠 JSON은 기획서 표에서 기계적으로 뽑는다.**
`scripts/extract-content.mjs`가 docs/의 두 문서를 읽어 `src/content/*.json`을 만든다. 표를 못 읽으면 추측하지 않고 멈춘다.
`npm run build`와 테스트가 `--check`로 JSON이 기획서와 같은지 확인하므로, 기획서와 데이터가 따로 놀 수 없다. 원안 v2.0 파일은 프로젝트에 없어 `sources/`는 만들지 않았다.

**D-005 적의 치명타는 확률 0%, 치명 피해 +50%로 둔다.**
부록 E.1 적 표에는 HP/ATK/DEF/SPD만 있다. 원작 원안의 적 치명타 값을 확인할 수 없어 0%로 둔다. 치명 피해 기본값은 유닛 공통 0.50을 따른다.
영향: 적 13종 전부. M2 전투 검증 뒤 필요하면 바꾼다.

**D-006 보유 조건이 붙은 전략 두 개의 제안 조건을 구조화했다.**
- `str_rear_command_net`: "후방 배치 가능 유닛 2명 이상 보유 시 또는 2~3장" → 2·3장에는 언제나, 1장에는 `rear_only`·`dual` 유닛을 2명 이상 보유할 때.
- `str_iron_frontline`: "전방 탱커/중장갑 유닛 2명 이상" → 전방 가능(`front_only`·`dual`)하면서 `syn_vanguard` 또는 `syn_heavy_armor` 태그가 있는 유닛 2명 이상. "탱커"를 뱅가드 태그로 읽었다.
보유는 대기석+편성(5.2의 소유 정의). 영향: strategies.json의 `offer.ownedCondition`.

**D-007 시너지 표시명.**
부록 B에는 ID만 있다. 본문이 부르는 이름(아비도스, 뱅가드, 택티컬, 메딕 …)을 표시명으로 쓰고, `syn_outlaw`는 v2.2의 「무법자 — 칠수인·헬멧단」, 고유 시너지는 「고유: 학생 이름」으로 둔다. 세부 이름은 UI 작업에서 바꿔도 된다(추출기의 `SYNERGY_NAME`).
시너지에 `category`(faction 14 · role · armor · unique · economy)를 붙였다. 커맨더가 세는 "14개 진영"(10.4)이 faction이다.

**D-008 시너지 집계 범위에 `rear_only`를 넣었다.**
v2.1 9장 타입 초안에는 없지만 부록 B의 히마리·리오 고유 시너지가 `rear_only` 집계다. 합법 집계 식은 `min(후방칸, R+D)`. 41종 모두 기획서 표의 최대 합법 집계와 같게 나온다.

**D-009 효과는 M0에서 명세만 있다.**
304개 효과 모두 `implementation: "spec_only"`, `handlers: []`다. 한국어 본문은 사람이 읽는 명세이고 실행하지 않는다(2장 원칙 5).
`npm run content:validate -- --require-implemented`는 지금 304건 실패하는 것이 정상이며, M3 완료 조건이 이 명령의 통과다.

**D-010 초상화는 폭 512px WebP로 줄여 저장소에 넣는다.**
기획서 13.4는 512×512 WebP를 권장하지만 생성 원본이 832×1216 세로형이라 비율을 지키고 폭만 512로 맞췄다(512×748, 품질 80, 60장 3.4MB). 정사각 크롭은 UI 쪽에서 `object-fit`으로 한다.

**D-011 RNG·해시·저장은 M1에서 만든다.**
M0 합격 기준(15장)은 설정·문서·스키마·카탈로그·build/typecheck다. `pack.json`에는 기획서 원문의 SHA-256만 기록했고, 콘텐츠 hash(canonical JSON SHA-256, 9.4)는 M1에서 저장 봉투와 함께 넣는다.
