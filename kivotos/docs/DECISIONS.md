# 결정 기록

기획서(v2.1 + v2.2 개정안)에 없거나 해석이 갈리는 부분을 어떻게 정했는지 남긴다. 형식: 결정 · 이유 · 영향 ID.
바꿀 때는 줄을 지우지 말고 새 항목에서 "D-00N 대체"라고 적는다.

## M0 (2026-10-29)

**D-001 v2.2 개정안을 구현 기준에 포함한다.**
v2.2는 v2.1과 함께 넘기도록 쓰인 개정안이다(개정안 머리말). 콘텐츠 팩은 `ba-content-2.2.0`, 규칙은 `ktfr-rules-2.2.0`으로 만든다.
되돌리려면 추출기에서 v2.2 단계를 빼면 된다. 영향: 유닛 태그 9건·이름 1건, `syn_jackpot`, `str_kaiser_loan`, 효과 304개, rules.json 경제 수치.

**D-002 이 게임은 저장소의 `kivotos/` 하위 폴더에 둔다.**
저장소에는 이미 다른 게임 두 개(루트 「황동의 생애」, `name-remains/`)가 있다. 기획서는 빈 저장소 루트를 전제로 썼지만 같은 구조를 `kivotos/` 안에 그대로 둔다.
배포 경로는 `/gamecode/kivotos/`. 루트 게임의 서비스 워커가 같은 사이트의 모든 화면 요청을 가로채므로 `tools/build.mjs`의 제외 목록에 `/kivotos/`를 넣었다. 이 게임이 만들 저장소·캐시 이름은 `kivotos-`로 시작한다.

**D-003 화면 계층은 교체 가능하게 분리하고, UI 프레임워크는 화면 쪽이 정한다.**
UI는 따로 설계 중이다(사용자 지시, 2026-10-29). 기획서 12.1은 React를 지정하지만, 규칙 코드는 어떤 프레임워크에도 묶지 않는다.
화면은 `src/app/gameClient.ts`의 `GameClient`만 쓴다. M0의 임시 화면은 의존성 없는 바닐라 TS다. 정식 화면이 React를 쓰면 그때 `src/ui/`와 함께 넣는다.
규칙은 docs/UI_CONTRACT.md, 강제는 tests/unit/architecture.test.ts와 tsconfig.core.json.

**D-004 콘텐츠 JSON은 기획서 표에서 기계적으로 뽑는다.**
`scripts/extract-content.mjs`가 docs/의 두 문서를 읽어 `src/content/*.json`을 만든다. 표를 못 읽으면 추측하지 않고 멈춘다.
`npm run build`와 테스트가 `--check`로 JSON이 기획서와 같은지 확인하므로, 기획서와 데이터가 따로 놀 수 없다. 원안 v2.0 파일은 프로젝트에 없어 `sources/`는 만들지 않았다.

**D-005 적의 치명타는 확률 0%, 치명 피해 +50%로 둔다.**
부록 E.1 적 표에는 HP/ATK/DEF/SPD만 있다. 원작 원안의 적 치명타 값을 확인할 수 없어 0%로 둔다. 치명 피해 기본값은 유닛 공통 0.50을 따른다.
영향: 적 13종 전부. M2 전투 검증 뒤 필요하면 바꾼다.

**D-006 보유 조건이 붙은 전략 두 개의 제안 조건을 구조화했다.**
- `str_rear_command_net`: "후방 배치 가능 유닛 2명 이상 보유 시 또는 2~3장" → 2·3장에는 언제나, 1장에는 `rear_only`·`dual` 유닛을 2명 이상 보유할 때.
- `str_iron_frontline`: "전방 탱커/중장갑 유닛 2명 이상" → 전방 가능(`front_only`·`dual`)하면서 `syn_vanguard` 또는 `syn_heavy_armor` 태그가 있는 유닛 2명 이상. "탱커"를 뱅가드 태그로 읽었다.
보유는 대기석+편성(5.2의 소유 정의). 영향: strategies.json의 `offer.ownedCondition`.

**D-007 시너지 표시명.**
부록 B에는 ID만 있다. 본문이 부르는 이름(아비도스, 뱅가드, 택티컬, 메딕 …)을 표시명으로 쓰고, `syn_outlaw`는 v2.2의 「무법자 — 칠수인·헬멧단」, 고유 시너지는 「고유: 학생 이름」으로 둔다. 세부 이름은 UI 작업에서 바꿔도 된다(추출기의 `SYNERGY_NAME`).
시너지에 `category`(faction 14 · role · armor · unique · economy)를 붙였다. 커맨더가 세는 "14개 진영"(10.4)이 faction이다.

**D-008 시너지 집계 범위에 `rear_only`를 넣었다.**
v2.1 9장 타입 초안에는 없지만 부록 B의 히마리·리오 고유 시너지가 `rear_only` 집계다. 합법 집계 식은 `min(후방칸, R+D)`. 41종 모두 기획서 표의 최대 합법 집계와 같게 나온다.

**D-009 효과는 M0에서 명세만 있다.**
304개 효과 모두 `implementation: "spec_only"`, `handlers: []`다. 한국어 본문은 사람이 읽는 명세이고 실행하지 않는다(2장 원칙 5).
`npm run content:validate -- --require-implemented`는 지금 304건 실패하는 것이 정상이며, M3 완료 조건이 이 명령의 통과다.

**D-010 초상화는 폭 512px WebP로 줄여 저장소에 넣는다.**
기획서 13.4는 512×512 WebP를 권장하지만 생성 원본이 832×1216 세로형이라 비율을 지키고 폭만 512로 맞췄다(512×748, 품질 80, 60장 3.4MB). 정사각 크롭은 UI 쪽에서 `object-fit`으로 한다.

**D-011 RNG·해시·저장은 M1에서 만든다.**
M0 합격 기준(15장)은 설정·문서·스키마·카탈로그·build/typecheck다. `pack.json`에는 기획서 원문의 SHA-256만 기록했고, 콘텐츠 hash(canonical JSON SHA-256, 9.4)는 M1에서 저장 봉투와 함께 넣는다.

**D-012 v2.3 개정안: 시너지 개편과 학생 100명 (2026-10-30 사용자 확정).**
`docs/GDD_v2.3_amendment.md`가 유닛·시너지 표를 통째로 대체한다. 진영 12종만 v2.1 효과를 유지하고, 흥신소68·C&C는 동아리로 옮겼다(ID 유지). 역할·장갑·고유·경제(한탕) 시너지와 그 효과는 사용자 지시로 폐기했고, 한탕에 딸린 금고(`CASH_OUT_VAULT`)도 함께 뺐다.
고유 시너지는 추천 11종만 넣었다. 예비안 5종(하루카·세리나·키리노·유우카·네루)은 팩에 없다. 고유 시너지 표시명은 「」로 감싼 원작 대사·별명이다(D-007의 "고유: 학생 이름"을 대체).
역할군 중 탱커·어태커는 구성원이 전부 전방 전용이라 최대 합법 집계가 4다. 계획안의 2/4/6을 2/3/4로 바꿨다.
플래티넘 「학원 대항전」·「총력전 만점」은 구성원 명단이 없는 집계 범위 `special`이다. 검증기는 이 둘의 구성원이 비어 있는지만 보고 도달 가능성 검사에서 뺀다.
효과 수 기준선(기본 공격 제외 1코≤3 … 5코≤7)은 pack.test가 지킨다.

## 오파츠·v2.3.1 (2026-10-30)

**D-013 오파츠를 콘텐츠 팩에 넣는다(팩 `ba-content-2.4.0`, 규칙 `ktfr-rules-2.4.0`).**
원본은 `docs/OOPARTS_v1.md`(사용자 확정안, 프로젝트 공유 폴더 design/ooparts.md와 같은 내용). 추출기가 2~5장 표를 `ooparts.json`으로, 효과 문장을 `effects.json`의 `eff_oop_*`(`oopart_container`, 명세만)로, 1.2절 획득 표를 `rules.ooparts`로 뽑는다.
보상·조합·레시피 공개는 전투 엔진 없이 정할 수 있어 `src/core/ooparts/ooparts.ts`에 먼저 구현했다. 쓰는 난수는 `reward` 스트림 하나다(12.2 RNG를 `src/core/rng.ts`로 함께 구현, 골든 테스트 통과).
해석: 한 등급의 후보가 바닥나면 아래 등급으로 내려가고(기획서), 아래도 없으면 위 등급으로 올라간다(기획서에 없음, 3택이 비지 않게).
레시피 공개 목록 `revealedRecipes`는 런이 아니라 프로필(메타) 저장에 둔다. 공개 전에는 보상 배지·도감에서 전설과 레시피를 숨기지만, 재료 가중치 ×2는 공개와 상관없이 적용한다(사용자 결정 2026-10-30).
전설은 재료의 대상 시너지를 물려받는다. 그래서 `kind: 'synergy'`인 전설이 에덴 조약 원본(트리니티·아리우스)과 유메 선배의 수첩(아비도스) 두 개다.

**D-014 v2.3.1: 상위 단계 시너지 본문을 풀어 쓴다.**
v2.1 6장은 "최고 도달 단계 하나만 등록하고 `[하위 효과 포함]` 문구가 있어도 본문에 없는 보너스를 추가하지 않는다"고 정했다. 그런데 v2.3의 동아리·역할군 상위 단계 33개는 `[하위 효과 포함]` 뒤에 새 효과만 적어서, 이 규칙대로 구현하면 4단계에서 2단계 효과가 사라진다(예: 미식연구회 4단계의 "별점 0개" 폭발, 어태커 4단계의 연속 타격 중첩, 서포터·컨트롤러 4단계의 지속 +1턴).
그래서 v2.3 개정안 5장의 상위 단계 본문을 하위 효과까지 모두 적는 문장으로 바꿨다. 다시 적은 숫자(탱커 받는 피해 -10% → -20%)는 대체, 다시 적지 않은 효과는 그대로 이어진다. 검증기가 V.번호 효과에 `[하위 효과 포함]`이 남으면 `TIER_REFERENCE` 오류를 낸다.
같은 이유로 발키리 3단계(v2.1 원문)는 2단계 "수배자" 지정을 본문에 명시해 유지한다(오파츠 「발키리 체포 영장」이 수배자를 쓴다). 진영 시너지의 다른 상위 단계는 v2.1에서 이미 숫자를 다시 적어 두었으므로 그대로 둔다.
게임개발부 4단계 "버그 3개 중 2개를 골라"는 누가 고르는지가 없어서 "준비 단계에서 고른 2개, 고르지 않으면 앞의 2개"로 정했다.

**D-015 v2.3.1 문구 정리.**
v2.1 부록 C에서 띄어쓰기가 빠진 효과 8개(`eff_saori_skill`, `eff_syn_valkyrie_3`, `eff_eq_goggles`, `eff_eq_headband`, `eff_eq_armband`, `eff_en_choir_rear_buff`, `eff_boss_kaiten_aura`, `eff_boss_binah_sandstorm`)를 v2.3 개정안 V.182~V.189로 대체했다. 수치·조건은 같다(발키리 3단계만 D-014).
폐기된 시너지 이름이 남은 문구 4곳을 고쳤다: 전략 「기동 타격대 탄막 교리」 약점(스트라이커 → 어태커), 「전방 중장갑 돌격 전술」 제안 문장(탱커/중장갑 → 탱커), 장비 전술 손목시계·방진 고글 추천(스트라이커/어설트 → 어태커).

**D-016 v2.3.2: 아리스를 2코로 내리고 AL-1S 각성을 넣는다(팩 `ba-content-2.5.0`, 사용자 요청 2026-10-30).**
아리스(4코)를 2코 기준선으로 내렸다(HP 1200·ATK 138, 스킬 140%, 필살기 160/185/225%, 후방 80%). 전방 충전 패시브 `eff_aris_passive`(C.300)는 그대로다.
고유 시너지 「빠밤! 레벨업」 경험치(처치 1, 정예·보스 3, 출전 전투 승리 1)가 30이고 3성 아리스를 보유하면 5코 각성 학생 `u_al1s`(AL-1S)로 바뀐다. 규칙은 v2.3 9장 표에 두고 추출기가 `UnitDefinition.awakening`·`awakenedFrom`으로 옮긴다. 정산 결정은 `src/core/awakening/awakening.ts`.
해석:
- 경험치는 개체가 아니라 런에 쌓는다(팔거나 합성해도 남음). 그래야 아리스 여러 장을 사고팔아도 진행이 꼬이지 않는다.
- 각성은 전투 중이 아니라 정산 때, 또는 준비 단계에서 3성 합성 직후 일어난다. 전투 도중 유닛 정의가 바뀌면 효과 등록·재생 로그가 복잡해진다.
- 사용자 조정(2026-10-30): 필요 경험치 20 → 30, 3성 아리스만 각성. 그래서 성급 +1·6G 보상은 없앴다(3성 → 3성 AL-1S). 대상은 3성 중 출전 → 먼저 얻은 순. 남은 아리스는 자동 판매, 이후 상점에 아리스 없음. AL-1S는 팔 수 없고 합성 대상이 아니다.
- AL-1S는 고유 시너지를 갈아 끼운다(「빠밤! 레벨업」 → 「이름 없는 신들의 왕녀」). 고유 0~1 원칙을 지키려고, 레벨업(레벨 10까지 +50%)은 새 고유 시너지 본문이 이어받는다.
- 아리스와 AL-1S는 한 편성에 함께 설 수 없으므로 시너지 구성원 수·F/R/D·최대 합법은 한 사람으로 센다(`synergyComposition`이 `awakenedFrom`을 건너뜀). 게임개발부·「엔딩 크레딧」은 여전히 4명 시너지다.
- 검증기 `AWAKENING`: 서로 가리킴, 각성 학생 상점 제외, 연쇄 각성 없음, 코스트 상승, 같은 구역, 고유 외 시너지 자리 유지.

**D-017 v2.3.3: 일반·정예 노드 난이도 1.5배(사용자 요청 2026-10-30).**
"최종 보스를 제외한 일반 잡몹과 정예를 1.5배 어렵게"를 일반·정예 노드 12개의 `statScaleBps`(적 HP·ATK 배율, A16) ×1.5로 구현했다(v2.3 개정안 10장, 예: 1-1 0.85 → 1.275, 3-4 1.4 → 2.1).
해석: 배율은 노드 단위라 보스 노드의 호위 적만 따로 올릴 수 없다. 처음에는 보스 노드 3개를 ×1로 두었고, 사용자 결정(같은 날)으로 1·2장 보스 노드도 ×1.5로 올렸다. 최종 보스 노드만 호위까지 ×1이다. DEF·SPD는 원래 규칙대로 배율을 받지 않는다. 패배 피해·보상은 그대로다.

**D-018 v2.3.4: 오파츠 3번째 전투 획득 삭제, 상점 장수 제한, 레벨 XP 상향(사용자 요청 2026-10-30).**
- 오파츠: "각 장 3번째 일반 전투 승리" 3택1을 없앴다. 런 시작·정예(장비에 더해)·1·2장 보스·구조 요청은 그대로다. 시뮬레이션상 판당 평균 약 5.9개 → 약 3.7개, 우연한 전설 완성 약 5% → 약 2%, 노릴 때 약 32% → 약 14%.
- 상점: v2.1 5.2 "개인 무한 재고"를 TFT식 코스트별 장수(30/25/18/10/9)로 바꿨다(v2.3 11.1). 남은 장수는 저장하지 않고 소유 학생과 지금 상점 칸에서 매번 계산한다(판매·갱신이 자동으로 장을 돌려줌, 저장 봉투 변경 없음). 코스트 안 추첨을 균등에서 남은 장수 비례로 바꿨고, 바닥난 코스트는 5.2의 "비어 있는 코스트 비례 재분배"를 그대로 쓴다.
